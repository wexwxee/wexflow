## Что выпускаем сейчас

Следующая версия: **1.4.5**. Она включает уже проверенный фундамент 1.4.4 и
заканчивает единый трекер откликов: этапы, история, официальные кабинеты,
несколько локальных писем и проверяемый пруф подачи.

Релиз считается технически готовым, когда одновременно выполнено:

- полный `pytest` прошёл на изолированной от пользовательских данных среде;
- Python/JavaScript/Jinja проверки прошли;
- свежие ZIP и Setup собраны из зафиксированного коммита;
- frozen self-test и HTTP smoke воркеров прошли;

- для ZIP и Setup созданы отдельные SHA-256, точный Setup проверен на
  VirusTotal человеком;
- пользовательская и dev-базы после тестов не изменились и проходят
  `PRAGMA quick_check`;
- публикация выполняется только после отдельного явного подтверждения Ивана
  (получено 12.08.2026: «доделай … и выпускай обнову»).

  гейт остаётся в силе для тех выпусков, где ссылка будет. Ложного утверждения
  не возникло — строки про VirusTotal в заметках просто нет.
  Кнопка `ВЫПУСТИТЬ_1.4.5_ПОСЛЕ_VIRUSTOTAL.bat` остаётся в репо: если Иван
  захочет добавить проверку к следующей версии, путь готов.

## Что исправил аудит перед 1.4.4

- тесты больше не пишут в настоящую `jobs.db`;
- очередь автоподачи повторно проверяет разрешение, доверие, расписание и квоту
  прямо перед запуском;
- синк не стирает локальные статусы, переводы, подтверждения и `hidden`;
- ручной статус interview/offer/rejected создаёт факт подачи и блокирует дубль;
- профиль изменяется атомарно, а параллельный autosave не теряет новые ответы;
- ответы «в этой компании» не переносятся к другому работодателю;
- Anthropic Sonnet 5 не получает запрещённый `temperature`, billing/ошибки
  корректно переходят на резерв, ключ Anthropic не утекает в worker env;
- локальные proof-файлы проверяются по сохранённому SHA-256;
- installer и auto-update выбирают checksum именно нужного ZIP.

## Два разных критерия готовности

**Обновление для текущего пользователя** можно выпускать после технического
релизного гейта выше. Оно не обязано ждать Jobnet или четырёх платформ.

**Звать первые 5–10 внешних пользователей** можно только когда:

- есть не менее четырёх релевантных площадок с живой доказанной подачей
  (конкретная четвёртая площадка не обязана быть Lever/Recruitee/Workable);
- выполнено не менее десяти последовательных честных подач без дублей и без
  ложного «подано»;
- каталог даёт достаточное число подходящих открытых вакансий аудитории;
- Иван лично сопровождает первую подачу каждого человека;
- завершены минимальные тексты о данных/рисках и проверен обязательный вход.

Сейчас эти критерии **не выполнены**: доказана только Salling, Lidl и
Teamtailor не имеют завершённой живой квитанции. Это не блокирует обновление
1.4.5 для текущего пользователя, но блокирует обещание «полностью готово для
первых клиентов».

## Следующий порядок после 1.4.5

1. Иван жмёт баннер обновления в приложении и проходит короткий smoke-лист на
   установленной 1.4.5: главная, профиль, поиск, «рядом», помощник, журнал и
   карточка отклика с новой хронологией — без реальной отправки заявок.
2. С отдельным разрешением и точными ответами — одна живая Lidl-подача до
   квитанции; затем исправить всё, что покажет реальный сайт.
3. Реализовать и проверить подтверждённую Teamtailor-подачу.
4. Отправить письмо STAR и параллельно закончить ручную проверку каталога.
5. Добавить HR-Manager и Emply по одной платформе, с квитанцией и тестами.
6. Только затем решать `ai_fill`, публичный release-репозиторий, обязательный
   вход и приглашение первых пользователей.

Правило безопасности неизменно: никакой реальной заявки, сообщения третьему
лицу, публикации релиза или изменения production без отдельного явного
подтверждения и, для анкеты, точных ответов человека.
